# Q: 檢討未什麼qubo_run_20260721_203644.pkl 的結果會這麼不理想

## Answer

Expanded from original query via graph vocab: [qubo, run, result, score, validation, test, train, tune, solver, seed, split, experiment]. 結論：主要問題不是 exact solver，而是 XGBoost 在 0.195% 正類且無 class weighting 的 patient-independent 場景下分數嚴重跨病人漂移；正類 score 中位數僅 0.00799，調參 threshold 下限卻是 0.3，lambda 下限 0.5 又會抑制短而不連續的訊號，造成 QUBO 在 50 個 seizure files 中 26 個輸出全零，嚴格事件命中由 baseline 36/55 降到 18/55。平均 seizure-file F1 雖由 0.2033 升至 0.2348，但 median 降為 0，改善集中在 chb05、chb07、chb09、chb10。反事實 wider grid 可把測試集宏觀 F1 推到 0.3595，但是假陽性率升高，證實 threshold grid 與 alpha=0.2 的目標不合適。另 logs 顯示此結果從 158 個已完成檔案的 checkpoint 續跑，而續跑前 XGBoost 已由 CPU 改成 CUDA hist；checkpoint 身分只含設定、不含 git revision 或 backend，因此本結果混合不同實作狀態，應視為不可重現的診斷樣本而非正式基準。
